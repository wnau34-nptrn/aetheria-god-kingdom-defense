# ผลตรวจและแก้ความสม่ำเสมอ 1x / 5x

ตัวเลขและหลักฐานหลังแก้ในเอกสารนี้อ้างอิง commit `a44dbc7` ซึ่งเป็นรอบแก้ฐานเวลา โค้ดรุ่นถัดมามีการแก้ทางเดินและการเลือกอาหารเพิ่ม ดูผลล่าสุดใน [BALANCE_REVIEW.th.md](BALANCE_REVIEW.th.md)

## ผลที่ได้

แก้ความต่างของอัตรายิงและเป้าหมายเดินที่เกิดจากการเร่งเวลา พร้อมแก้การซื้อคาราวานโดยไม่มีทรัพยากร และการรายงานสร้างบ้าน/ป้อมสำเร็จทั้งที่หาที่วางไม่ได้

ชุดตรวจสุดท้ายผ่าน **56 unit/integration tests**, **5 browser tests** และ production build การตรวจรอบนี้ใช้สถานการณ์ควบคุมเพื่อแยกบั๊กออกจากการสุ่มและการตัดสินใจของผู้เล่น ไม่ใช่ผลทดสอบสมดุลทั้งเกม

## ปัญหาที่ทำซ้ำได้ก่อนแก้

เทียบโค้ดฐาน commit `e55e25e11d254fbd8b3a0accf975eaf0b4261746` ด้วยโลกเริ่มต้นที่ทำซ้ำได้ 2 ชุด (seed 1234 และ 5678) และเดิน **13 วินาทีของเวลาเกมเท่ากัน**:

| สิ่งที่วัด | ก่อนแก้ 1x | ก่อนแก้ 5x | หลังแก้ 1x และ 5x |
|---|---:|---:|---:|
| ความเสียหายป้อมต่อเป้านิ่ง | 252 | 224 | 252 ทั้งคู่ |
| ตำแหน่งทหารลาดตระเวน X | 5.43958 | 1.23427 | 5.43958 ทั้งคู่ |
| ตำแหน่งชาวนา X | -30.23162 | -25.86973 | -30.23162 ทั้งคู่ |
| อาหารที่ชาวนาผลิตใน fixture นี้ | 15 | 15 | 15 ทั้งคู่ |

ตัวเลขไม่ยืนยันว่าการผลิตอาหารก่อนแก้ต่างกันในทุกช่วงเวลา: fixture นี้ผลิตเท่ากัน แต่เป้าหมายและเส้นทางชาวนาต่างกัน ส่วนป้อมเสียความเสียหายไปหนึ่งนัดที่ 5x (ประมาณ 11.1%) ในช่วงที่วัด

สาเหตุคือขนาด simulation delta ต่างกันตาม speed และจำนวน substeps ตัวจับเวลา cooldown/workTimer ถูกตัดเป็นช่วงต่างกัน อีกทั้งเส้นทางลาดตระเวน วิ่งเล่น และพรวนดินอ้าง elapsedTime ของภาพแทนเวลา simulation

## การแก้ฐานเวลา

- เพิ่ม simulation accumulator ใช้ tick คงที่ **0.05 วินาที (20Hz)** เมื่อเดินเวลาเกมเท่ากัน 1x/2.5x/5x จะเรียกกลไกด้วยขนาด tick เดียวกัน
- ย้ายวงจรวันคืน/ความเสียหายจากแสง การเพิ่มศรัทธา/ความก้าวหน้า การเติบโตพืช การเดินทาง รถม้า/สัตว์ กระสุน งานชาวบ้าน ป้อมและอสูรเข้า simulation tick
- ใช้เวลา simulation สำหรับเป้าหมายเดินของทหาร เด็ก และชาวนา
- แยกการแสดงแสง/นาฬิกาออกจากการเดินเวลา กล้องและเอฟเฟกต์ภาพยังอัปเดตได้ขณะ pause
- เมื่อ pause หรือเปิดเหตุการณ์ ไม่เก็บเวลาหยุดมาทบเพื่อไล่ catch-up หลังกลับมา ปุ่มเวลาจะแสดง pause ระหว่างเหตุการณ์และคืนค่าความเร็วเดิมหลังปิด
- ปุ่มข้ามกลางคืนขณะ pause แสดงเวลา/แสงได้ แต่เวฟเริ่มเมื่อ resume แทนการสร้างศัตรูระหว่างหยุด

ยังคง frame delta clamp 0.05 วินาทีและ render delay 42ms เดิมไว้ ดังนั้น 5x เป็นอัตราต่อเวลาที่ระบบรับเข้า ไม่รับประกันว่าเครื่องที่เรนเดอร์ช้าจะเดิน simulation ได้ห้าเท่าของนาฬิกาจริง การปลดข้อจำกัดเพื่อเพิ่ม FPS เป็นงานแยกที่ต้องวัด

## ปัญหาเหตุการณ์ที่แก้

### 1. ซื้อคาราวานฟรีเมื่อทุกตัวเลือกจ่ายไม่ไหว

ตั้ง food/wood/faith เป็น 0 แล้วเลือกซื้อเกวียน เดิมได้รับอาหาร 30 และรถม้า 1 คัน แม้ต้องจ่ายศรัทธา 15 เพราะ handler ยกเว้นการตรวจต้นทุนเมื่อไม่มีตัวเลือกใดจ่ายได้

ตอนนี้ทุกตัวเลือกที่มีต้นทุนต้องจ่ายไหวเสมอ แสดงเหตุผลที่เลือกไม่ได้และคงหน้าต่างไว้ ปุ่มปิด/ESC ยังใช้ได้ จึงไม่มีการบังคับให้ซื้อหรือค้างในหน้าต่าง

### 2. หาที่สร้างไม่ได้แต่หักของและแจ้งว่าสำเร็จ

ใช้ fixture ที่มีเขตฐานอาคารปิดตำแหน่งที่สภาจะเลือก เดิมไม้ลด 20 → 5, คนเพิ่ม 7 → 9 และบอกว่าสร้างบ้านแล้ว ทั้งที่จำนวนบ้านไม่เพิ่ม

ตอนนี้หาจุดวางให้ได้ก่อนหักต้นทุนหรือเพิ่มยูนิต หากหาไม่พบ จะเก็บทรัพยากรไว้ แสดงคำเตือน และให้เลือกทางอื่นหรือปิดได้ ใช้หลักเดียวกันกับทางเลือกสร้างป้อม ไม่เปลี่ยนต้นทุนหรือผลของกรณีที่สร้างสำเร็จ

หลักฐานดิบ: [เหตุการณ์ก่อนแก้](speed-review/events-before.json), [หลังแก้](speed-review/events-after.json)

## ขอบเขตการตรวจ

### Logic / DOM integration

รันโค้ดเกมและ geometry จริงใน jsdom โดยควบคุมนาฬิกาและสุ่มเริ่มต้น Stub เฉพาะ pixels/audio เพื่อทดสอบ logic ได้เร็วและทำซ้ำได้ การตั้ง HP/ตำแหน่ง/ทรัพยากรเป็น **fixture ทดสอบที่ระบุไว้** ไม่ใช่การเล่นตามปกติหรือการวัดความยาก

- 10 สถานการณ์: ทหาร ป้อม อสูร อุกกาบาต ชาวนา ชาวประมง ขนแร่ ก่อสร้าง ซ่อม และลาดตระเวน
- เทียบ 1x/2.5x/5x ใน 2 seed สำหรับสถานการณ์เหล่านี้ ตรวจผลจริง เช่น damage, resources, progress, HP และตำแหน่ง
- ตรวจ frame delta 1/60 และ 0.033 วินาทีเพิ่มเติมในป้อม ชาวนา ลาดตระเวน และขนแร่
- ตรวจ pause และการคืนความเร็ว 0x/1x/2.5x/5x เมื่อสลับครบทั้ง 5 แท็บเหตุการณ์
- ตรวจผลเชิงตัวเลข/จำนวนวัตถุ/ยูนิตของตัวเลือกทั้ง **15 ข้อ** และกรณีเงินไม่พอ/ไม่มีพื้นที่

ผลผ่านไม่ได้หมายความว่าทั้งโลกจะ deterministic ทุกอย่างที่ทุก speed: RNG ของงาน simulation กับภาพยังไม่ได้แยก stream และการเปิดเหตุการณ์อัตโนมัติยังใช้ presentation delta เดิม การ auto-advance ยุคที่ 5x ก็เป็นพฤติกรรมเดิมที่ยังคงอยู่

### Browser / WebGL จริง

รัน Chromium + SwiftShader ผ่านหน้าเกมจริง ไม่ stub renderer ชุด browser 5 ข้อตรวจเริ่มเกม, กล้อง/HUD ตามชุดเดิม, pause, กระสุนค้างขณะหยุด, save/reload/failure, touch ใช้พลังครั้งเดียว, WebGL unavailable, การเดิน/หยุด/คืนความเร็ว 1x/5x, ปฏิเสธคาราวาน และคำเตือนพื้นที่สภา

ภาพหน้าต่างที่ใช้ตรวจ: [คาราวานที่จ่ายไม่ไหว](speed-review/screenshots/unaffordable-caravan.png), [สภาที่ไม่มีพื้นที่](speed-review/screenshots/council-no-plot.png) Toast เป็นข้อความชั่วคราว อาจหมดเวลาก่อนภาพถูกบันทึกบน software renderer; ข้อความถูกตรวจด้วย browser assertion ก่อน capture แล้ว

ไม่มี uncaught page error ในกรณีเล่นปกติที่ตรวจ ข้อผิดพลาด WebGL unavailable เป็นกรณีจำลองที่คาดไว้ ไม่ใช่ hardware GPU benchmark หรือการเล่นครบทุกยุคหลาย run การตรวจความยากและความสนุกยังต้องเล่นซ้ำหลังแก้เวลา

## ทำซ้ำ

```bash
npm ci
npm test
npm run build
npx playwright install chromium
npm run test:browser
node tests/compare-speed.mjs
node tests/compare-events.mjs
```

หากใช้ Chromium ในระบบ ตั้ง `CHROMIUM_PATH=/usr/bin/chromium` เฉพาะคำสั่ง browser ได้ สองสคริปต์เปรียบเทียบจะเขียนเฉพาะไฟล์ `after.json` / `events-after.json` โดยปริยาย

ทำซ้ำ baseline โดยส่งโค้ดจาก commit เดิมผ่าน `SPEED_SOURCE` และระบุไฟล์ผลด้วย `SPEED_REPORT` เช่น:

```bash
git show e55e25e:src/legacy/game.js > /tmp/aetheria-baseline-game.js
SPEED_SOURCE=/tmp/aetheria-baseline-game.js SPEED_REPORT=/tmp/aetheria-speed-before.json node tests/compare-speed.mjs
```

ต้นฉบับใน `original/` ไม่ถูกแก้ ส่วนการเก็บคน/เมืองต่อเนื่องข้ามยุคและ full world save ยังเป็นงานระยะถัดไปตามแผน
