# ผลตรวจ UX ผ่านกลางวัน–กลางคืนด้วย UI ใหม่

เซสชันนี้ไม่มี Browser/IAB tool จึงใช้ Playwright Chromium ที่ติดตั้งใน workspace

รอบนี้ตรวจการเตรียมเมือง คำเตือนก่อนบุก การใช้เมนู/พลัง การพักเวลา และการเล่นต่อหลังทัพหนุน โดยใช้ WebGL จริงและอินพุตผ่านปุ่ม เมาส์ และการแตะ ข้อมูลนี้เป็นการเล่นตามนโยบายสคริปต์ ใช้ระบุปัญหาการใช้งานและตรวจความถูกต้อง การประเมินความสนุกยังต้องอาศัยผู้เล่นจริง

## วิธีเล่นที่ใช้ตรวจ

- เริ่ม context ใหม่ต่ออุปกรณ์ ไม่มีเซฟเดิม ใช้ค่าทรัพยากรและการสุ่มตามเกม
- เตรียมทหารเพิ่มหนึ่งนายและหอคอยหนึ่งหลัง ใช้ฝนเมื่ออาหาร/ความหิวถึงเงื่อนไข ใช้สายฟ้าได้ไม่เกินสามครั้งเมื่อจ่ายได้ เลือกข้อเสนอที่จ่ายได้ในเหตุการณ์ธรรมชาติ หรือปิดเหตุการณ์เมื่อมันขัดจังหวะอินพุตอื่น
- เดินเวลาที่ 5× เป็นหลัก เปลี่ยน 1× ตรงก่อนผ่าน 18:00/20:00 และพักเพื่อเล็ง/บันทึกภาพ ไม่มีการข้ามเวลา เปลี่ยนยุค เติมทรัพยากร เขียน world state หรือแทน RNG/นาฬิกาในรอบต่อเนื่อง
- การเล็งอาศัยตำแหน่งในโลกที่อ่านผ่าน API และแปลงเป็นพิกัดจอ จากนั้นใช้ pointer/touch จริง จึงไม่ใช่หลักฐานว่ามนุษย์จะเล็งได้เร็วเท่ากัน
- คอมใช้ 400×300 ระหว่างเดินเวลา และ 1024×640 ตอนใช้พลัง/ตรวจภาพ มือถือใช้ 390×844 ตลอด ซูมออกด้วยปุ่มกล้องระหว่างเดินเวลาและรีเซ็ตกล้องเพื่อบันทึกภาพ เพื่อให้ทำงานบน software renderer ได้ จึงไม่ใช้เวลา wall-clock นี้สรุป FPS บนอุปกรณ์จริง
- เล่นผ่านทัพหนุน รุ่งเช้า และเวลาตั้งต้นของวันถัดไป แม้ประชากรจะหมดตามกติกา sandbox

ตัวทดสอบเคยหยุดในรอบตั้งค่า รวมถึงจังหวะเหตุการณ์สุ่มบังปุ่มความเร็ว จากนั้นแก้การจัดการเหตุการณ์/พื้นที่เล็ง/การตรวจสถานะแบนเนอร์ ไม่นับรอบที่หยุดก่อนจบเป็นรอบผ่าน

## รุ่นที่ตรวจและการตรวจซ้ำ

รอบต่อเนื่องเริ่มจาก build ที่แก้เสียงและข้อความศรัทธาไม่พอแล้ว เก็บ hash ใน [metadata](day-night-review/metadata.json) และ [build manifest](day-night-review/build-manifest.json) ก่อนเดินเวลา:

- game.js ตรงกับ source ใน commit `0978ebcca6dc96600f84865d25f674349cc18c1a`; metadata ระบุ parent commit ขณะรันจาก worktree ที่ยังไม่ commit และยืนยันเนื้อหาด้วย SHA-256
- CSS ของรอบต่อเนื่องเป็นรุ่น `d3cc470` ก่อนเก็บตำแหน่งข้อความบนจอเตี้ย; การย้ายข้อความตรวจซ้ำแยกด้วยเบราว์เซอร์และภาพ feedback
- หลังพบเมืองว่าง จึงเพิ่มคำแนะนำใน commit `2a14278018c1ade82f9717ea3b7b7756f919d440` และตรวจ recovery ด้วย unit/browser fixture แยกจากรอบต่อเนื่อง ภาพรุ่งเช้าของรอบต่อเนื่องจึงยังเป็นข้อความก่อนเพิ่มคำแนะนำ

การกด 1× ใกล้จุดเปลี่ยนมี latency ของอินพุต ข้อมูล snapshot ยืนยันสถานะ 1× หลังการกด แต่ไม่ได้เก็บทุก tick ระหว่าง pointer event จึงไม่ใช้รอบนี้ยืนยันว่า tick ข้าม 18:00/20:00 เกิดที่ 1× ทุกครั้ง และไม่ใช่สองรอบแยกความเร็ว 1× กับ 5×

อินพุต browser ของ regression ใช้ Web Audio จริง โดยห่อ `createGain` เพื่อเก็บ reference มาวัดค่า ไม่มีการแทนเสียงด้วย mock สำหรับการตรวจ mute ส่วน fixture เมืองว่างทำเครื่องหมายชาวบ้านเดิมไม่อยู่ในฉากเพื่อพิสูจน์ UI ฟื้นเมือง และไม่ได้เติมทรัพยากรหรือบังคับเวลา

คำสั่งทำซ้ำรอบต่อเนื่อง (เปิด production preview แยกไว้ก่อน และใช้โฟลเดอร์หลักฐานใหม่ทุกครั้ง):

```sh
CHROMIUM_PATH=/usr/bin/chromium \
CYCLE_EVIDENCE=/tmp/aetheria-cycle-review \
PLAYTEST_URL=http://127.0.0.1:5173 \
node tests/day-night-playthrough.mjs
```

คำสั่งตรวจ regression:

```sh
npm test
CHROMIUM_PATH=/usr/bin/chromium npm run test:browser
```
