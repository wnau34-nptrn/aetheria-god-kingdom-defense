# ตัดสินใจตามสถานการณ์ — AI จัดคนและเป้าหมาย

วิธีเล่นหลักเปลี่ยนจากเลือกคน/ทหารแล้วสั่งทีละหน่วย เป็นเลือกสิ่งสำคัญให้เมืองและกองทัพ การ์ดบน HUD แสดงตัวเลือกสามข้อที่สัมพันธ์กับสถานการณ์ ไม่ต้องเปิดแผงเพิ่ม ไม่ต้องแตะเป้าหมายหรือเลือกที่ก่อสร้าง

## การเล่น

| สถานการณ์ | ตัวเลือกตัวอย่าง | สิ่งที่ AI ทำ |
|---|---|---|
| ขาดวัสดุ | เร่งเก็บไม้ / เร่งขุดแร่ / เพิ่มเสบียง | จัดคนงาน เลือกแหล่งปลอดภัย เก็บและขนส่งวิหาร |
| เสบียงน้อย | เพิ่มเสบียง / เร่งเก็บไม้ / บริหารสมดุล | เปลี่ยนลำดับงาน โดยเก็บของระหว่างขนไว้ |
| อาคารเสียหาย | ฟื้นฟูเมือง / เร่งเก็บไม้ / เพิ่มเสบียง | ส่งคนซ่อมอาคารที่ปลอดภัย แล้วคืนงานเดิมเมื่อซ่อมครบ |
| เมืองพร้อมลงทุนหรือที่พักเต็ม | ขยายที่พัก / เสริมป้อม / พัฒนายุค ตามบริบท | ตรวจเงื่อนไข เลือกจุดและคนสร้าง ใช้ของจริง |
| ใกล้เวลาบุกหรือรอทัพหนุน | ป้องกันเมือง / เสริมป้อม / เพิ่มเสบียง | เตรียมแนวรับและเมืองพร้อมกัน |
| กองทัพหมดระหว่างศึก | เสริมทหาร / เสริมป้อม / คืน AI หรือเพิ่มแรงงานเมื่อเมืองไม่มีคนงาน | ให้สร้างแนวป้องกันกลับมา แล้วทหารใหม่เข้าแผนเดิม |
| มีอสูร | ป้องกันเมือง / กวาดล้างอสูร / ถอนกำลัง | เลือกภัย จัดทหารและตำแหน่ง เปลี่ยนเป้าหมายเมื่อภัยเดิมหมด |

แถบสถานะแสดงแผนเมือง/แผนรบกับจำนวนผู้ปฏิบัติ ปุ่ม **เสริมทหาร 25 ศรัทธา / เพิ่มแรงงาน 20 ศรัทธา / คืน AI** อยู่บนการ์ดตลอด ใช้ต้นทุนและเงื่อนไขเดิม การเสริมทหารยังใช้กลไกแต่งตั้งชาวบ้านเดิมเมื่อมีคนเหมาะสม ไม่ใช่ระบบค่ายฝึกใหม่

แผนเมืองกับแผนรบแยกกัน สั่งเก็บไม้แล้วสั่งถอนทหาร คนงานยังเก็บไม้ในที่ปลอดภัย สลับแท็บ **เมือง / รบ / อัตโนมัติ** เพื่อเลือกนโยบายอีกด้านได้โดยไม่ย้ายกล้อง ไม่เปลี่ยนความเร็ว และไม่ล้างงาน ตัวอย่าง: ระหว่างรบสลับเมืองแล้วเลือกฟื้นฟูเมือง จากนั้นกลับแท็บรบเพื่อจัดการกองทัพ

แตะทรัพยากรบน HUD เพื่อดูแหล่งที่มา จำนวนในคลังและของระหว่างขน ปุ่มในรายละเอียดให้ AI จัดคนเก็บทรัพยากรนั้นได้โดยไม่เลือกคนงาน ไม้/แร่/ผลไม้เพิ่มคลังเมื่อส่งถึงวิหาร ไม่มีการเสกของจากคำสั่ง

## กติกา AI

- ประเมินผู้ปฏิบัติ/เป้าหมายทุก 2 วินาที simulation และทันทีที่รับการตัดสินใจ จึงทำงานเหมือนกันที่ 1x และ 5x และหยุดเมื่อพักเกม
- งานทรัพยากรใช้ประมาณ 60% ของช่างเมือง โดยเหลืออย่างน้อยหนึ่งคนเมื่อมีหลายคน ไม่แย่งคนที่ติดงานก่อสร้าง ไม่เปลี่ยนเด็กหรือทหารเป็นคนงาน
- งานซ่อมใช้อาคารที่เสร็จแล้วและไม่มีภัยใกล้เคียง คนงานคืนงานเดิมเมื่อเปลี่ยนนโยบายหรือซ่อมครบ โครงการก่อสร้างใหม่ไม่ถูกคำสั่งซ่อมเก่าเขียนทับ
- ขยายที่พัก/เสริมป้อมใช้ไม้ 25 + แร่ 18 ต่อหลัง ตรวจที่และต้นทุนก่อนจ่าย ไม่มีพื้นที่ปลอดภัยไม่สร้างและไม่หักของ การสั่งหนึ่งครั้งสร้างหนึ่งโครงการ
- ป้องกันเมืองเลือกแนวใกล้ภัย กวาดล้างให้ความสำคัญกับภัยคุกคามวิหาร/เมืองก่อน ทหารใหม่เข้าร่วมแผนที่กำลังใช้ ไม่ต้องเลือกกองซ้ำ
- ถอนกำลังกลับบริเวณฐาน ไม่หาเป้าหมายใหม่ การโจมตีที่เริ่มท่าแล้วจบหนึ่งครั้งก่อนถอนตามกติกาปะทะเดิม
- คนงานใช้การหลบภัยเฉพาะพื้นที่เดิม เก็บ cargo/งานไว้แล้วกลับเมื่อปลอดภัย กลางคืนไม่หยุดงานทั้งเกาะ
- การ์ดย่อของคำถามสภาแสดงพร้อมตัวเลือกหลัก ไม่แย่งกล้อง/keyboard focus และไม่หยุดเวลา เปิด **เรื่องราว** เพื่อหยุดอ่านรายละเอียดได้
- พัฒนายุคปกติรักษานโยบาย คนและงาน สร้างโลก sandbox ใหม่ล้างนโยบายเดิม ปุ่มเซฟยังเป็น checkpoint ทรัพยากร/ยุค ไม่ใช่เซฟนโยบายหรือโลกครบชุด

## การควบคุมโดยตรงเป็นตัวเลือกเสริม

เปิดเมนู → **รูปแบบการบัญชาการ → ควบคุมยูนิตโดยตรง** เพื่อใช้คำสั่งเลือกกอง/คนงานและแตะตำแหน่งเดิม การสลับโหมดล้างคำสั่งที่โหมดก่อนจัดไว้และยกเลิกการเล็ง แต่ไม่ทิ้ง cargo หรือรื้อโครงการก่อสร้าง โหมดที่เลือกจำในเบราว์เซอร์

รายละเอียดกลไกฐานอยู่ใน [ARMY_RTS.th.md](ARMY_RTS.th.md) และ [ECONOMY_RTS.th.md](ECONOMY_RTS.th.md) ระบบค่ายฝึก ทหารหลายประเภทและยานรบยังอยู่ใน [แผนพัฒนา](ROADMAP.th.md)

## วิธีตรวจ

`tests/strategy.test.js` ใช้ DOM/geometry/game loop จริงใน harness ที่แทนภาพและเสียง ตรวจการส่งไม้/โจมตีจริงที่ 1x/5x การหาเป้าหมายใหม่ ทหารเสริม ถอนหลังปะทะ ก่อสร้าง/จ่ายครั้งเดียว/ไม่จ่ายเมื่อไม่มีที่ งานซ่อมและโครงการเดิม ของระหว่างขน แหล่งอันตราย การขึ้นยุคและการ์ดไม่หยุดเวลา

`tests/strategy.spec.js` ใช้ Chromium software WebGL กดผ่าน UI บน 1280×800 และจอสัมผัส 390×844: สั่งเก็บไม้แล้วรอส่งคลังจริง สั่งรบ รับทหารเสริมและถอนกำลังโดยไม่เลือกหน่วย เปลี่ยนงานผ่านแผงทรัพยากร และตรวจคำตอบสภากับคำสั่งรบกดได้พร้อมกัน รวมจอแนวนอน 400×300

ช่วงรบใน browser test ใช้ศัตรูสองตัวแบบควบคุมเพื่อตรวจการเปลี่ยนเป้าหมาย ไม่ใช่การเล่นผ่านคืนแรกตามธรรมชาติหรือการรับรองสมดุลเกม ข้อมูลที่ browser fixture เปลี่ยนแยกจากการกดคำสั่งจริง ชุด browser เดิมตรวจกลไกโดยเปิดโหมดควบคุมโดยตรงผ่านเมนูจริง ส่วน production smoke ตรวจโหมดตัดสินใจที่ผู้เล่นใหม่ได้รับ

สภาพแวดล้อมไม่มีเครื่องมือ Browser/CUA สำหรับควบคุมโดยตรง จึงใช้ Playwright ตาม fallback ของทักษะ playtest หลักฐานนี้ไม่ใช่การวัด FPS บน GPU จริงหรือผลความสนุกจากผู้เล่นมนุษย์

การทดลองผ่าน UI ต่อเนื่องบนฐาน `7a74846` ตั้งแต่กลางวันถึงหลังรุ่งเช้า (เร่ง 5x และพักผ่านปุ่มเพื่อเก็บภาพ) พบกรณีทหารหมดแต่ยังเสนอคำสั่งเคลื่อนทัพ จึงแก้ให้เสนอการเสริมกำลังแทน มีกรณีควบคุมใน browser ตรวจการแต่งตั้งทหารจากการ์ดนี้และกลับเข้าแผนเดิม ไม่ใช่การรับรองว่าทหารสี่นายชนะคืนแรกได้โดยไม่ใช้พลังเทพ
