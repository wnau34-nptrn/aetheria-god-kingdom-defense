# AETHERIA: หน้าจอที่ให้เกาะเป็นจุดสนใจ

## แนวทาง

ปรับเฉพาะ UX/UI ของเกมเดิม พื้นผิวสีน้ำเงินเข้ม `#101d28` ตัวอักษร `#edf2ee` ข้อความรอง `#adbdb5` และทองอ่อน `#ddc58b` สำหรับการเลือกและทรัพยากร ใช้เส้นขอบบาง มุม 8–16px และไอคอนเส้นชุดเดียวกัน คงภาพโลก 3D ระบบจำลอง สมดุล ค่าใช้พลัง และเซฟรูปแบบเดิม

- ซ้ายบน: ชื่อเกม ยุค วัน เวลา และความเร็ว
- ขวาบน: อาณาจักร แผนที่ เหตุการณ์ เมนู
- ล่างกลาง: ศรัทธา อาหาร คน อสูร เตือนคืนแรก และพลังทั้งหก
- รายละเอียดเปิดทีละแผง ปิดด้วยปุ่มปิด Esc หรือแตะนอกแผง คืนโฟกัสให้ปุ่มที่เปิด
- แผงเมนูรวมเซฟ เสียง วิธีเล่น การแสดงผล และเครื่องมือโลก/ยุค
- หน้าตัดสินใจเน้นเรื่องราวและผลลัพธ์ เครื่องมือภาพกับการเปลี่ยนเรื่องราวอยู่ในส่วนขยาย

แผงควบคุมและปุ่มลัดพลังไม่ส่งอินพุตไปโลกขณะเปิดแผง แผ่นรองรับการแตะป้องกันการร่ายพลังเมื่อต้องการปิดเมนู กล้องหยุดรับคีย์ที่กดค้างเมื่อเปิดแผง แผงเลื่อนด้วยนิ้วได้ และเคารพการตั้งค่าลดการเคลื่อนไหว

## การเทียบกับภาพแนวคิด

ภาพแนวคิดสร้างก่อนเขียนโค้ดจากภาพเกมจริง ตรวจภาพแนวคิดและภาพเบราว์เซอร์ด้วยเครื่องมือดูภาพ ตรวจ 6 จุด: โครงวาง, สี, ตัวอักษร, ไอคอน, ระยะห่าง, พื้นที่เห็นเกาะ

ปรับจากภาพแนวคิดโดยตั้งใจ:

1. แถบพลังเดสก์ท็อปกว้างสูงสุด 680px เพื่อเพิ่มพื้นที่เล่น และใช้บรรทัดเตือนที่มีอยู่จริง ไม่เพิ่มตัวชี้วัดใหม่
2. ชื่อพลังย่อเป็นภาษาไทยที่อ่านได้ในปุ่มมือถือ คงรายละเอียดใน tooltip และวิธีเล่น
3. แสดงต้นทุนจริงของเกมเป็นศรัทธาทุกพลัง ไม่ใช้สัญลักษณ์หิน/น้ำซึ่งภาพแนวคิดสร้างขึ้น
4. ภาพโลกเป็นการเรนเดอร์เกมจริง ไม่มีการใช้ภาพแนวคิดทับ canvas หรือเพิ่มฉาก/แอสเซ็ตใหม่
5. ภาพแนวคิดมีขนาด 1586×992; ตรวจ implementation ที่ 1280×800, 390×844 และจอแนวนอน 400×300, 640×480, 844×390 ตาม breakpoints จริง

ข้อความหน้าจอเริ่มต้นที่อนุญาต: AETHERIA, ยุค, วัน/เวลา/ช่วงวัน, ปุ่มความเร็ว, เมนูทั้งสี่, ทรัพยากรทั้งสี่, ข้อความภัยคุกคามจริง, ชื่อและต้นทุนพลังทั้งหก ไม่มีข้อความการตลาดหรือภารกิจที่เพิ่มขึ้น

## ตรวจสอบ

ใช้ Playwright Chromium และ WebGL จริง เนื่องจากไม่มี Browser/IAB tool ในเซสชันนี้ ทดสอบ DOM ควบคู่ภาพหน้าจอ รวมการเปิด/สลับ/ปิดแผง การคืนโฟกัส การเปิดส่วนขยาย เมนูเสียง การเซฟ การเลือกพลัง การหยุดเวลา และป้องกันการร่ายพลังเมื่อแตะปิดเมนู การทดสอบอัตโนมัติเป็นหลักฐานความถูกต้องของหน้าจอและการทำงาน ไม่ใช่ผลประเมินความสนุกจากผู้เล่นจริง

### ผลตรวจภาพและการทำงาน

ตรวจภาพแนวคิดด้วย `view_image` เทียบภาพ build ล่าสุดจาก Playwright รวมภาพอาณาจักรและเมนูบนคอม และเมนู/เหตุการณ์บนมือถือแล้ว

| จุดตรวจ | ผลและสิ่งที่ปรับ |
| --- | --- |
| โครงวาง | ชื่อ/เวลาซ้ายบน เมนูขวาบน พลังล่างกลาง ตรงแนวคิด; ย่อ dock ตามข้อยกเว้นข้างต้น |
| ตัวอักษร | ชื่อพลัง 12px คอม / 11px มือถือ; ทรัพยากร 18px / 16px; หัวข้อแผง 21px; ตรวจการตัดบรรทัดภาษาไทย |
| สีและพื้นผิว | ใช้ tokens สีเข้ม/ทองอ่อนเดียวกัน ไม่มีเส้นเรืองแสงหรือกรอบทองทุกแผง |
| ไอคอน | SVG เส้นน้ำหนักเดียวกันบนเมนู พลัง ทรัพยากร และกล้อง; รักษาความหมายต้นทุนศรัทธาจริง |
| ระยะและพื้นที่เล่น | HUD ปกติบนคอมมี bounding boxes รวมประมาณ 15.2% ของ viewport; ไม่เปิดแผงรายละเอียดตอนเริ่ม |
| สถานะและ responsive | ตรวจคอม มือถือ และแนวนอน; แก้ข้อความความคิดล้น; คืนโฟกัสหลังปิดแผง; ปุ่มเวลาอยู่เหนือแผ่นกันอินพุตของแผง |

ตรวจรายการข้อความหน้าจอเริ่มต้นแล้ว ไม่มีหัวข้อหรือระบบใหม่ที่นอกเหนือรายการที่ระบุ การเปลี่ยนชื่อเป็นชื่อสั้นและการย่อขนาดเป็นข้อยกเว้นที่บันทึกไว้ ไม่พบความคลาดเคลื่อนด้านภาพที่ยังต้องแก้ก่อนเผยแพร่ ภาพแนวคิดไม่ได้ถูกนำมาใช้แทน UI จริง

การตรวจ local: unit/integration 80 กรณีผ่าน; browser suite ครอบคลุม 17 สถานการณ์ (รวม 2 สถานการณ์เมนูใหม่); production subpath บนคอม/มือถือ 2 สถานการณ์ผ่าน ไม่มี page error หรือ request ล้มเหลว และเปิดเมนูพร้อมกดพักเวลาได้จริงบนทั้งสอง viewport การเผยแพร่ main ยังต้องผ่าน CI ทั้งชุดและตรวจ URL ที่ deploy พร้อม SHA ตาม workflow เดิม
